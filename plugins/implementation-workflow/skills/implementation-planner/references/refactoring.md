# Refactoring

リファクタリングは任意の美化ではない。LLM が安全にコードを読んで変更するための品質維持である。

- 名前は実際の処理、責務、戻り値、失敗条件と一致させる。
- 関数名やコンポーネント名が実態とズレたまま修正を重ねない。
- 適切に分割し、1つの関数やコンポーネントに複数責務を詰め込まない。
- 同じ概念を別名で表現しない。
- 用語、型、schema、UI 文言、API 名の記述差異を減らす。
- 似た処理の重複は、仕様差か偶然の重複かを確認する。
- 小手先の局所修正で構造を悪化させない。
- リファクタリングは test、type、static analysis、manual check で保護する。
