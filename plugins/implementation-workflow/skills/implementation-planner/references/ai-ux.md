# AI UX

AI はユーザーの入力負荷、言語化負荷、認知負荷を下げるために使う。

- ユーザーはやりたいことを正確に言語化できない前提で設計する。
- 対話型 UI を優先候補にする。ただし単純なチャット本文だけで終わらせない。
- AI の出力は、候補、カード、表、差分、ステップ、編集可能な提案、グラフ、プレビューに変換する。
- ユーザーが採用、編集、却下、再生成、根拠確認できるようにする。
- 外部送信、課金、削除、公開など不可逆操作では、プレビュー、確認、取消、根拠、失敗時復帰を必須にする。
- ユーザーの入力、本人素材、ライブ生成、AI 生成結果などの主成果物を、別素材、seed、sample、mock、demo asset で置き換えて成功扱いしない。明示的に「サンプル」と表示しても、ユーザーが期待する成果物が本人入力から生まれていないなら成功ではない。失敗時は失敗として扱い、再試行、入力変更、既存の本物の候補選択、後で再開の導線を設計する。
- seed / sample / demo asset を使う場合は、初期状態、説明、テスト、セーフモードなど本人入力と切り離された用途に限定し、ユーザー生成物の結果表示や success state に混ぜない。

Before / After 例（生テキスト → 操作可能な結果）:

- Bad: AI 返信を本文にそのまま流す / Good: `返信案` カード＋`採用` `編集して使う` `別案を出す` と、引用した根拠箇所へのリンク。
- Bad: `要約しました` とテキスト塊 / Good: 箇条書き要約＋`元の該当箇所を開く` で出典を確認できる。
- Bad: `送信しました`（AI 生成メールを即送信）/ Good: 送信前にプレビューと宛先・送信先を表示し、`送信` `下書きに戻す`、送信後は `送信しました（取り消し可）`。
- Bad: 自由入力 `指示を入力` だけ / Good: よくある意図を候補ボタンで提示し、足りなければ自由入力で補完できる。
- Bad: ユーザーの写真からの動画生成に失敗したため、別のサンプル動画を結果として表示する / Good: 失敗理由と復旧方法を出し、同じ入力で再試行、写真変更、既に生成済みの本人候補を選ぶ導線に戻す。
